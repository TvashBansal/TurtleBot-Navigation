# Permanently archived experiment evidence

This folder is **tracked by Git**. It contains selected results copied from temporary `outputs/` runs. Every archived run must include a `manifest.json` recording file hashes and reproduction instructions.

- `kinematic/`: controller/software debug evidence only. This does **not** demonstrate the required MuJoCo task, camera image detection or contact physics.
- `mujoco/`: only store results after the MuJoCo backend has actually been run and verified. Capture a diagnostic MP4 with `--video` when possible.
- `tests/`: pytest JUnit XML, console logs, source revision and counts generated by `scripts/record_tests.py`.
- `hardware/`: future physical results, only after supervised lab verification. The provided archival scripts currently accept kinematic/MuJoCo experiment folders, not ROS bagfiles.

## Archive and verify selected experiments

Test suite evidence can be recorded and archived as well:

```bash
python scripts/record_tests.py --out outputs/pytest_report
python scripts/archive_run.py outputs/pytest_report --name test_report_01
python scripts/reproduce_archive.py results/tests/test_report_01
```


Run from the repository root in GitHub Codespaces:

```bash
python -m turtlebot_integrated.cli run --backend mujoco --scenario nominal --seed 7 --video --out outputs/nominal_seed7
python scripts/archive_run.py outputs/nominal_seed7 --name nominal_seed7
python scripts/verify_archive.py results
python scripts/reproduce_archive.py results/mujoco/nominal_seed7
```

To run and archive a multi-seed experiment:

```bash
python -m turtlebot_integrated.cli suite --backend mujoco --seeds 5 --out outputs/mujoco_suite
python scripts/archive_run.py outputs/mujoco_suite --name repeated_5_seeds
python scripts/verify_archive.py results
```

The archive script **never overwrites** previously archived experiments. Each archived run stores input parameters, measured metrics, plots, trajectories and any captured video. The `reproduce_archive.py` utility re-runs the experiment in `outputs/` and writes a numerical comparison; simulations can have floating-point variation across systems. Run unit tests separately with `python -m pytest -q`.

Before pushing to GitHub: keep committed MP4s reasonably small. Standard GitHub Git objects above 50 MB produce warnings, and files above 100 MB are rejected. Compress lengthy clips or configure **Git LFS** for large MP4s *before committing them*; check your account's LFS quotas. GitHub Actions artifacts are temporary and **not** a substitute for committing selected evidence here.

```bash
git add results/
git commit -m "Archive verified simulation evidence"
git push
```

**Integrity note:** Hash validation only confirms that stored files have not changed since the archive manifest was generated. It does not prove the simulation is correct. A reproduction uses the current checked-out code unless the tutor checks out the git commit recorded in the archive manifest. The tutor should check the backend field and experiment limitations before interpreting results.
